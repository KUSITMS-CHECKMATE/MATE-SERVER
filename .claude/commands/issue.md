# GitHub Issue 생성 커맨드
## 사용법

```
/issue <작업 내용을 간단히 설명>
```

## 동작 순서

1. `$ARGUMENTS` 기반 작업 유형 판단(버그 수정, 기능 제안, 작업)
2. 판단된 유형에 해당하는 템플릿 파일 확인
3. 유형별 작성 가이드에 따른 본문 구성
4. 초안 제시 및 생성 여부 확인 요청
5. 확인 시 `gh issue create` 실행, 생성된 이슈 URL 출력
6. 수정 요청 시 해당 항목 반영 후 재확인

## 유형 판단 기준

| 판단 근거 | 분류 |
|---|---|
| 버그, 오류, 에러 관련 언급 | 버그 수정 |
| 신규 동작, 기능 추가 요청 | 기능 제안 |
| 세팅, 문서, 잡일성 요청 | 작업 |

분류가 애매한 경우 사용자에게 직접 확인한다.

## 유형별 작성 가이드

### 버그 수정

- 템플릿 경로: `.github/ISSUE_TEMPLATE/bug_report.md`
- 라벨: `fix`
- 제목 프리픽스: `fix: `
- Description: 문제 현상 한 줄 요약
- Task: 원인 파악, 수정, 재현 테스트 및 검증, 영향 범위 확인 4항목 고정
- Reference: 로그 또는 스크린샷이 있는 경우에만 작성

### 기능 제안

- 템플릿 경로: `.github/ISSUE_TEMPLATE/feature_request.md`
- 라벨: `feat`
- 제목 프리픽스: `feat: `
- 기능 설명: 대상 기능 서술
- 구현 방향: API 및 기능 동작, 테스트 및 검증, 문서 업데이트 3항목
- 참고: 화면 또는 기획 링크가 있는 경우에만 작성

### 작업

- 템플릿 경로: `.github/ISSUE_TEMPLATE/task.md`
- 라벨: 없음
- 제목 프리픽스: 상황에 맞는 프리픽스(`chore: `, `refactor: ` 등)
- Description: 수행할 작업 내용 요약
- Task: 작업 수행, 테스트 및 검증, 영향 범위 확인 3항목
- Reference: 참고할 자료가 있는 경우에만 작성

## 이슈 생성 명령

사용자 확인 후 아래 순서로 실행한다. 본문은 특수문자와 마크다운 이스케이프 오류를 방지하기 위해 임시 파일로 작성한 뒤 `--body-file`로 전달한다.

```bash
# 1. 본문을 임시 파일에 저장
cat > /tmp/issue_body.md << 'EOF'
<채워진 템플릿 내용>
EOF

# 2. 이슈 생성(작업 유형은 라벨이 없으므로 --label 생략)
gh issue create \
  --title "<제목 프리픽스><제목>" \
  --label "<라벨>" \
  --body-file /tmp/issue_body.md

# 3. 임시 파일 삭제
rm /tmp/issue_body.md
```

생성 완료 후 반환된 이슈 URL을 사용자에게 출력한다.
