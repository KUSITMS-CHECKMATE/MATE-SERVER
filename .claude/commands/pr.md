# GitHub PR 생성 커맨드

## 사용법

인자 없이 `/pr` 실행, 현재 브랜치 기준으로 동작한다.

## 동작 순서

1. `git log`와 `git diff <base-branch>...HEAD`를 통한 변경사항 파악
2. 브랜치명에서 이슈 번호와 타입 추출(예: `feat/#12-detail-concurrency`에서 이슈 12, 타입 feat)
3. 변경사항과 관련된 테스트 실행 및 통과 여부 확인, 실행한 명령어 기록
4. `.github/pull_request_template.md` 필독 후 구조 그대로 본문 구성
5. 초안 제시 및 생성 여부 확인 요청
6. 확인 시 `gh pr create` 실행(base `dev` 고정), 생성된 PR URL 출력
7. 수정 요청 시 해당 항목 반영 후 재확인

## 필드별 작성 규칙

### PR 제목

브랜치 타입에 대응하는 콜론 프리픽스와 한글 제목으로 구성한다.

| 브랜치 타입 | 제목 프리픽스 |
|---|---|
| `feat` | `feat: ` |
| `fix` | `fix: ` |
| `refactor` | `refactor: ` |
| `docs` | `docs: ` |
| `test` | `test: ` |
| `chore` | `chore: ` |

### 요약

변경 배경과 목적을 한 줄로 서술한다.

### 관련 이슈

브랜치명에서 추출한 번호로 `Closes #번호` 형식으로 연결한다. 번호 추출이 불가능한 경우 사용자에게 확인한다.

### 변경 사항

브랜치 타입과 무관하게 `git diff`로 파악한 실제 코드 변경과 작업 내용을 검토해서 해당하는 항목을 모두 체크한다(복수 선택 가능).

### 작업 내용

실제 변경을 기능 단위로 나열한다. 커밋 단위 나열은 지양한다.

### 테스트

관련 테스트를 실제로 작성 및 실행해서 통과를 확인한 뒤 로컬 테스트 완료 항목을 체크한다. 테스트 방법 항목에는 실행한 빌드 및 테스트 명령어를 그대로 기재한다.

```
- 테스트 방법:
  - ./gradlew compileJava compileTestJava
  - ./gradlew test --tests "패키지.클래스명1" --tests "패키지.클래스명2"
```

## PR 생성 명령

사용자 확인 후 아래 순서로 실행한다. 본문은 특수문자와 마크다운 이스케이프 오류를 방지하기 위해 임시 파일로 작성한 뒤 `--body-file`로 전달한다.

```bash
# 1. 본문을 임시 파일에 저장
cat > /tmp/pr_body.md << 'EOF'
<채워진 템플릿 내용>
EOF

# 2. PR 생성
gh pr create \
  --title "<제목 프리픽스><제목>" \
  --body-file /tmp/pr_body.md \
  --base dev

# 3. 임시 파일 삭제
rm /tmp/pr_body.md
```

생성 완료 후 반환된 PR URL을 사용자에게 출력한다.

## 주의사항

base 브랜치는 항상 `dev`로 설정한다. 다른 브랜치로 보내는 경우 반드시 사용자에게 확인한다.
